# 06 UI

Single-page app: **React + Vite + TypeScript**, server state in **TanStack Query**, API client generated from `openapi.yaml` (`openapi-typescript` + `openapi-fetch`). Built to `web/dist` and embedded in the Go binary with `go:embed` (one image, D-53). Everything is live via SSE (10). No external assets at runtime.

## Architecture rules

| ID | Rule |
|---|---|
| UI-001 | The SPA uses only the public `/api/v1` REST API and `/api/v1/events`; there are no UI-private endpoints (ARC-001). CI regenerates the TS client from `openapi.yaml` and fails on a diff. |
| UI-002 | Cookie sessions: mutations send `X-CSRF-Token` (from `GET /me` `csrf_token`). Login/logout are full-page navigations to `/auth/*`. |
| UI-003 | Never `dangerouslySetInnerHTML`. All strings from manifests, labels, cluster status, grant reasons and the IdP render as text. |
| UI-004 | Layout works at 360 px; tables scroll inside their own container. |
| UI-005 | Go serves `web/dist` at `/` with SPA fallback (unknown non-`/api`, non-`/auth` GET → `index.html`); hashed assets get `Cache-Control: immutable`, `index.html` gets `no-store`. CSP `default-src 'self'; connect-src 'self'; frame-ancestors 'none'`. |
| UI-006 | A committed stub `web/dist/index.html` keeps `go build`/`go test` working without Node; `make web` builds the real bundle; the release image always builds it (multi-stage, Node stage). |

## Live data

| ID | Rule |
|---|---|
| UI-020 | One `EventSource('/api/v1/events')` per tab, opened after login. Each event type maps to a cache update: payload written with `setQueryData` for the matching detail key and patched into list keys; `stack.removed` removes; `reset` and every reconnect after a gap invalidate all queries. |
| UI-021 | No interval polling for anything the event catalogue covers. Queries use `staleTime: Infinity` while the stream is live and fall back to `refetchInterval: 30s` while it is down. |
| UI-022 | Connection indicator in the header: **Live** (green dot + text), **Reconnecting…** (amber), **Offline** (red). |
| UI-023 | Stale-data banner: when the stream has been down > 5 s, an amber banner "Live updates paused — showing data from 10:42:13. Reconnecting…"; after 30 s it turns red with a "Retry now" button. When a target is unreachable (`target.status`), every stack on it shows "Cluster prod-eu unreachable — status as of 10:41". |
| UI-024 | Live changes are visible but calm: changed rows flash once (disabled under `prefers-reduced-motion`); counters (ready/desired) update in place; lists never reorder under the cursor while a menu or dialog is open. |
| UI-025 | `session.ended` → modal "Your session ended" with a login button; no silent redirect that loses form input. |

## Accessibility basics

| ID | Rule |
|---|---|
| UI-030 | Semantic HTML (`<nav>`, `<main>`, `<table>` with `<th scope>`), every control reachable and operable by keyboard, visible focus ring, dialogs trap focus and restore it on close. |
| UI-031 | One `aria-live="polite"` region announces only meaningful transitions for what the user is looking at (deployment succeeded/failed/rolled back, grant approved/expired, connection lost/restored), at most one message per 5 s. Replica counter ticks are not announced. |
| UI-032 | Colour is never the only signal (badges have text and icons); text contrast ≥ WCAG AA; respects `prefers-reduced-motion` and `prefers-color-scheme`. |
| UI-033 | Playwright smoke runs `@axe-core/playwright` on the main screens and fails on serious/critical violations. |

## UI conventions

- Build screens only from `web/src/components/ui/` (index.ts): `Page`, `PageHeader` (icon, title, subtitle, badges, actions), `StatCard`/`StatGrid`, `SectionCard`, `DataTable` (+ `RowMenu` row actions), `EmptyState`, `KeyValueList`, `Stepper`/`Timeline`, `Notice`, `Modal`/`ConfirmDialog`, `FormField`, `Btn`/`AsyncBtn`, `Tabs`, `Skeleton*`, `Avatar`, `Icon`, and the `StatusBadge`/`TierBadge`/`ProfileBadge` badges. No raw `<table>`, hand-styled buttons or ad-hoc cards.
- Feedback: every mutation ends in `useToast()` (errors use `role="alert"`); destructive flows use `ConfirmDialog` (typed confirmation for prod); inline guidance uses `Notice` (calm, never a solid colour block); loading uses `skeleton`; hints use `Tip`.
- Colour comes from daisyUI theme tokens only (no hex), must pass axe in all five switcher themes, and state is never colour alone (UI-032). Tailwind class names must appear literally in source (no `tooltip-${x}`).
- Untrusted strings are rendered as text children only (UI-003). The CSP stays strict: no inline style tags; dynamic values use the React `style` prop (CSSOM).
