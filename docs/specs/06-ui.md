# 06 UI

Single-page app: **React + Vite + TypeScript**, server state in **TanStack Query**, API client generated from `openapi.yaml` (`openapi-typescript` + `openapi-fetch`). Built to `web/dist` and embedded in the Go binary with `go:embed` (one image, D-53). Everything is live via SSE (10). No external assets at runtime.

## Architecture rules

| ID | Rule |
|---|---|
| UI-001 | The SPA uses only the public `/api/v1` REST API and `/api/v1/events`; there are no UI-private endpoints (ARC-001). CI regenerates the TS client from `openapi.yaml` and fails on a diff. |
| UI-002 | Cookie sessions: mutations send `X-CSRF-Token` (from `GET /me` `csrf_token`). Login/logout are full-page navigations to `/auth/*`. |
| UI-003 | Never `dangerouslySetInnerHTML`. All strings from manifests, labels, cluster status, grant reasons and the IdP render as text. |
| UI-004 | Layout works at 360 px; tables scroll inside their own container. |
| UI-005 | Go serves `web/dist` at `/` with SPA fallback (unknown non-`/api`, non-`/auth` GET → `index.html`); hashed assets get `Cache-Control: immutable`, `index.html` gets `no-store`. CSP `default-src 'self'; connect-src 'self'; frame-ancestors 'none'`. |
| UI-006 | A committed stub `web/dist/index.html` keeps `go build`/`go test` working without Node; `make web` builds the real bundle; the release image always builds it (multi-stage, Node stage). |

## Live data

| ID | Rule |
|---|---|
| UI-020 | One `EventSource('/api/v1/events')` per tab, opened after login. Each event type maps to a cache update: payload written with `setQueryData` for the matching detail key and patched into list keys; `stack.removed` removes; `reset` and every reconnect after a gap invalidate all queries. |
| UI-021 | No interval polling for anything the event catalogue covers. Queries use `staleTime: Infinity` while the stream is live and fall back to `refetchInterval: 30s` while it is down. |
| UI-022 | Connection indicator in the header: **Live** (green dot + text), **Reconnecting…** (amber), **Offline** (red). |
| UI-023 | Stale-data banner: when the stream has been down > 5 s, an amber banner "Live updates paused — showing data from 10:42:13. Reconnecting…"; after 30 s it turns red with a "Retry now" button. When a target is unreachable (`target.status`), every stack on it shows "Cluster prod-eu unreachable — status as of 10:41". |
| UI-024 | Live changes are visible but calm: changed rows flash once (disabled under `prefers-reduced-motion`); counters (ready/desired) update in place; lists never reorder under the cursor while a menu or dialog is open. |
| UI-025 | `session.ended` → modal "Your session ended" with a login button; no silent redirect that loses form input. |

## Indicators (must be obvious)

| ID | Rule |
|---|---|
| UI-010 | `<ProfileBadge>` is the only way profile is shown. **Managed rollout** (circular-arrow icon, solid blue, white text), **As-is — no safety net** (warning triangle, solid amber, black text, 2 px dashed border), *(Docker track)* **With Parachute** (shield, solid teal). Text always present. |
| UI-011 | Badge appears in every stack row, the stack header (large), every deployment row/page, the revision page, and the deploy and image-update dialogs. Drafts: grey "No profile yet". |
| UI-012 | Document title on a stack page ends with `[PROD]`/`[NON-PROD]` and `[ROLLOUT]`/`[AS-IS]`/`[PARACHUTE]`. |
| UI-013 | Deploy dialog: user picks the profile radio matching the revision (`confirm_safety_profile`); on prod types the namespace slug (`confirm_environment_tier=prod`). Button text names both ("Deploy rev 3 to PROD — Managed rollout"). `as_is` adds the checkbox "I understand there is no automatic rollback". |
| UI-014 | Profile change vs deployed revision → red line "Safety profile changes: Managed rollout → As-is" in the dialog. |
| UI-015 | `<TierBadge>`: **PROD** (solid red, white text, lock icon) or **non-prod** (grey outline) next to every namespace, target and stack name. |
| UI-016 | Prod action buttons show grant state live: "Access until 14:30 — 52 min left" (countdown), "Awaiting approval", or "Request prod access" (prefilled link). A `grant_required` response opens the request form. At expiry the buttons switch without reload. |
| UI-017 | `rollout_frozen` → red banner "Automatic updates stopped after a failed rollback — an admin must deploy a revision". |
| UI-018 | Break-glass sessions: red banner on every page, "grant bypassed" label on prod actions. |

## Accessibility basics

| ID | Rule |
|---|---|
| UI-030 | Semantic HTML (`<nav>`, `<main>`, `<table>` with `<th scope>`), every control reachable and operable by keyboard, visible focus ring, dialogs trap focus and restore it on close. |
| UI-031 | One `aria-live="polite"` region announces only meaningful transitions for what the user is looking at (deployment succeeded/failed/rolled back, grant approved/expired, connection lost/restored), at most one message per 5 s. Replica counter ticks are not announced. |
| UI-032 | Colour is never the only signal (badges have text and icons); text contrast ≥ WCAG AA; respects `prefers-reduced-motion` and `prefers-color-scheme`. |
| UI-033 | Playwright smoke runs `@axe-core/playwright` on the main screens and fails on serious/critical violations. |

## Screens

| Screen | Route | Live behaviour | Actions (→ API) |
|---|---|---|---|
| Login | `/login` | — | `/auth/login`, `/auth/break-glass` |
| No access | `/no-access` | — | — |
| Overview | `/` | Stacks grouped by namespace with tier, profile, health, ready/desired; target cards (reachable, last event); pending approvals count; my grants with countdown | — |
| Namespace | `/n/:ns` | Stacks list live; tier, approver group, assets, policy summary | create asset, create stack |
| Asset | `/n/:ns/assets/:asset` | Stacks of the asset live | edit, delete |
| Stack | `/n/:ns/s/:stack` | Header badges + health; workloads table (`Kind/name`, ready/desired, image, digest) updating from informers; current rollout progress bar per workload; drift list; digest updates available; recent deployments; grant state (UI-016) | new revision, deploy, image update per container, teardown, request access |
| New revision | `/n/:ns/s/:stack/revisions/new` | — (draft kept in `sessionStorage`) | `POST .../revisions`; violations inline |
| Revision | `/n/:ns/s/:stack/revisions/:n` | — | deploy dialog |
| Deployment | `/deployments/:id` | Status timeline, per-workload rollout table, "rolling back to rev N", grant id; output refetched on each update | approve / reject / cancel |
| Request access | `/access/request` | — | `POST /access-grants` |
| My grants | `/access` | Status and countdown live; approval/denial appears without reload | revoke/cancel own |
| Approver queue | `/access/approvals` | New requests appear live for namespaces in `approver_for`; removed when someone else decides | approve (optionally shorter), deny with note |
| Active grants | `/access/active` | Countdown, auto-moves to expired | revoke |
| Approvals | `/approvals` | Pending deployments live | approve/reject |
| Audit | `/audit` | Live feed (newest on top, pause button; paused shows "N new events") with filters (namespace, action, actor, grant) | — |
| Admin: access | `/admin/access` | — | role bindings; set namespace `approver_group`; configured tokens read-only |
| Admin: policy | `/admin/policy` | — | `PUT /policies/global` |
| Admin: targets | `/admin/targets` | Reachability, informer sync state, last error live | — (config only) |
| Tokens | `/tokens` | — | read-only list |

Docker track (later) adds Parachute columns, freeze panel and hold/release actions on the stack page.

Not in v1 UI: pod logs, exec, restart, scale, YAML editor with syntax highlighting, notifications in the browser.
